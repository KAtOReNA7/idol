## v212 时制定的开发方案（历史起点）

首要问题是用户打开作品却看不了。已登录的 B 站嵌入播放器在《Magnetic》上选档后打开原站，本站停在 0 秒、640 × 360。《BILLIONAIRE》的 RUTUBE 和 YouTube 原版在最近一次正式检查都没有起播。目前 605 支有原视频的作品中，126 支配置了同剪辑备选，这个数字只统计映射。其余 479 支有原视频、尚未配置这类备选。[正式站播放记录](worklogs/20261122-v212-release.md) · [PRD](PRD.md) · [AGENTS](../../AGENTS.md)

### 1. 先修能否在本站观看

- **第一批查两支 MV 和四个舞台。** 从《BILLIONAIRE》《Magnetic》进入现有作品详情，另查 B 站独占的《CRUSH》《Password》《Teddy Bear》《ELEVEN -Japanese ver.-》舞台，逐条保留精确版本、分 P、区间和评分归属。已有登录选档外跳记录可直接复用。《BILLIONAIRE》的 YG 和 Weverse 页面共用同一 YouTube 视频，后发舞蹈版是另一剪辑。优先验证发行方允许站内播放的同版来源，已有失败记录的线路在片源或接入条件变化后再试。[原版与官方出处](worklogs/20261122-v212-release.md) · [四条舞台来源](evidence/20261122-v211/playback-sources.json)
- **改作品详情的选源和失败反馈。** 现有组件同时只挂一个播放器，但 126 条映射均可依次切换 RUTUBE 和 YouTube。将同版候选保留在内部，按逐作品实测结果选一个可用入口，让用户点击一次即可在详情内打开。发生上游错误时保留评分草稿、作品和返回位置，提供可操作的重试或准确的暂无站内片源提示。有经证实的替代才换源。四个舞台的原站链接可保留为出处，另计站内可播数。[选源逻辑](../../apps/idol-site/lib/idol/work-playback.ts) · [播放器](../../apps/idol-site/components/work-video-player.tsx) · [同版映射](../../apps/idol-site/data/verified-work-players.json)
- **可用来源与接入条件。** 先用发行方支持的嵌入播放器。如果取得权利方允许本网站使用的高清媒体地址，可用原生播放器固定对应高清轨道，保留原视频 ID 与评分关系。B 站接入须能在站内选到账号与原片可用的最高档，并能阻止低清降档。现有外链播放器未满足这两个条件。没有独立同版来源的条目保留待解决，继续处理其他作品。没有备选的 479 支仍须逐项判断原入口的可用性。
- **验收与扩展。** 在正式作品页用 Codex 自带浏览器静音短播，记两个递增的进度、实际解码宽高、可读的码率和是否外跳。每批报告“实际起播数 / 本批尝试数”和未过作品、原因。两支 MV 和四个舞台分别记录结果。有成功样本后按相同供应商和版本规则扩到其余作品。

## 三、优先修复的发现

### 1. 正式锁文件命中严重依赖公告

`npm audit --omit=dev` 报告 6 个受影响包，含 1 个 critical、3 个 high、2 个 moderate。生产依赖中的 critical 为 `next@16.3.4`。包含开发与构建依赖后共 33 个受影响包，critical 为 `next` 和 `react-server-dom-webpack`。本项目同时使用 `vinext@1.0.0-beta.5`、Vite 和 Cloudflare Worker，依赖分类本身不足以判断最终 Worker 的实际暴露面。

优先确认受公告影响的功能是否进入客户端、SSR、RSC 或构建工具，再选择相容的修复版本。每组升级都重新构建并核对 Worker、资源清单、匿名读取和 owner 拒绝路径。若升级改变受保护产物哈希，逐项核对源码、引用与产物差异后再更新对应凭据。[正式依赖声明](../../apps/idol-site/package.json) · [锁文件](../../apps/idol-site/package-lock.json)

### 2. 舞台导入应把现有保护变成不可省略、可恢复的执行流程

正式导入器含 56 个 Python `assert`，身份和选择策略模块另有 29、58 个。包长度及摘要、目标集合、前像新鲜度、日志与来源约束依赖其中多项断言。解释器优化模式会省略断言。正常模式下的 69 项近期回归通过。另一个具体问题是写入阶段依次替换证据、来源、状态三个文件，使用固定临时文件名。单文件替换有保护，进程中断或两次导入重叠时缺少整批恢复边界。

把生产输入校验改为始终执行并给出明确错误的函数。写入前统一准备并校验旧摘要、三个新文件和目标集合。用单写入者约束、唯一暂存路径及可恢复事务记录处理重试。验收须覆盖普通与优化解释器、三个文件替换之间中断、相同批次重跑、竞争写入。运行这些用例只需隔离副本和合成记录。[导入器](../../apps/idol-site/scripts/merge-stage-batch.py) · [来源身份](../../apps/idol-site/scripts/stage_source_identity.py) · [选择策略](../../apps/idol-site/scripts/stage_selection_policy.py) · [现有保护测试](../../apps/idol-site/tests/stage-owner-preflight.test.cjs)

### 3. 现有测试覆盖广，但整套结果暂时不能支撑大规模改动

正式 Node 套件共 **3,956 项，2,764 通过、1,153 失败、39 跳过**，失败分布在 137 个文件。另行复跑最近的 69 项采用测试全部通过，独立的偏好统计套件 31 项通过。旧加载器把模块名拼成 `follower-count.mjs.ts`，单这一条缺文件错误就出现 256 次。两个旧夹具对同一公开媒体模块的导入拒绝另触发 325 次。运行时缺陷、测试夹具失效和只适用于历史版本的断言需要分别查明。

还有两个可独立复现的工具问题。补充片源校验器启动时拒绝当前模块依赖 `./stage-source`，尚未核到输入数据。CSS HTTP 夹具固定期待 37 张主题样式表，实际构建找到 50 张，导致后续处理器测试未启动。现有搜索浏览器脚本在手机宽度首项断言前超时。实际构建的作品列表和返回焦点流程通过。正式 `package.json` 缺少统一 `test`、`typecheck` 和 `verify` 命令。本提交也没有 GitHub Actions 工作流。[测试失败逐文件索引](evidence/20261121-project-audit/verification.json) · [补充片源校验器](../../apps/idol-site/scripts/validate-supplements.mjs) · [CSS 夹具构建](../../apps/idol-site/tests/css-http-fixture-build.mjs)

默认 lint 返回 **2,944 个错误、1,000 个警告**，其中 2,725 个错误来自测试目录。应为 CommonJS 测试配置匹配的规则，将运行时代码的 Hooks、类型和导航问题单独修复。历史断言应在对应版本仍可执行，每次退役都留下对应版本及当下的替代验收。[ESLint 配置](../../apps/idol-site/eslint.config.mjs)

### 4. 用户打开首页就承担了大量详情数据

本次正式构建的首页静态依赖含 48 个 JS、7 个 CSS，合计 3,353,399 字节，gzip 后 579,973 字节。仅公开媒体和参与参考两个 JS 块分别占 1,152,439 和 662,464 个原始字节，gzip 合计 199,197 字节。真实本地 Worker 返回的合成全目录另有 1,080,832 个 JSON 字节，同一数据库的 IVE 范围响应为 46,055 字节。此样本含 614 个作品、51 个合成人物、0 条评分关系。构建图体积与目录响应大小均不能推算线上 LCP。

先将详情才需要的图片映射、参与参考、作品播放器或偏好统计移出首页静态依赖，再评估卡片索引与按需详情读取。保留已经按需加载的团体索引。拆分后验证作品总数、筛选、下一首队列、返回焦点、刷新取消及跨团历史关系。把「首访静态 gzip 比本次下降 25%」作为建议的首轮目标，并在同一设备和网络条件下比较可用时间。[首页入口](../../apps/idol-site/app/page.tsx) · [构建图测量](../../apps/idol-site/scripts/report-client-graph.mjs) · [目录投影](../../apps/idol-site/lib/idol/artist-catalog.ts)

### 5. 单图读取和集中核对有具体的服务端开销

公开媒体读取每次先取得全公开目录，再遍历成员与评分关系照片确认授权。底层已有按当前状态与 generation 区分的原生目录缓存，但每张图仍触发公开投影和遍历。建议复用同一 owner 分区、快照、epoch、generation 范围内的公开照片索引。保留前后状态核对及 R2 对象的 SHA、长度和格式验证。

实时舞台核对已把评分与完整日志放在同一个 D1 batch。用仓库迁移重建的 SQLite 显示，按作品取前像需要扫描原生记录，完整日志还需要临时排序。相同模式下，按既有复合字符串主键取目标可使用现有索引。先改目标读取并测量，再根据规模评估日志索引或事务内的完整性汇总。需要维持完整日志证明、所有状态的匹配和前后状态一致性。[公开媒体读取](../../apps/idol-site/lib/idol/public-reader.ts) · [原生目录缓存](../../apps/idol-site/lib/idol/native-reader.ts) · [批量核对](../../apps/idol-site/lib/idol/stage-owner-preflight.ts)

### 6. 手机键盘导航和首次本地运行有可见的问题

390 像素下，在首页数据加载完成后打开导航，按 Escape 仍展开。继续 Tab 可以把焦点移到遮在菜单下的正文。两宽的作品详情返回能够恢复原卡片焦点，这个行为应作为改动对照。修正菜单的关闭、可见焦点范围和触发按钮焦点恢复。ifeye、izna 的检查须穿过 Shadow DOM。
