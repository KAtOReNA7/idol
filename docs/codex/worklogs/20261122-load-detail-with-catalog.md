# 直达 MV 时同时请求页面代码与作品资料

正式 v215 中，IVE 和 ADYA 的两次独立导航显示，作品详情的首批脚本都在局部目录接收完后才开始下载。以页面文档发起导航为零点，IVE 在 919 ms 发起目录请求，2,715 ms 接收完成，2,722 ms 才发起详情脚本。ADYA 对应为 1,013、2,595 和 2,601 ms。页面会等待这两类资源齐备后才显示播放按钮。[上批三个团的正式对照](20261122-v215-release.md)

有效作品直达地址可以在现有目录读取的同时开始加载同一份界面代码。React 渲染复用浏览器已经下载的模块。沿用既有作品 ID、可读范围、保存和版本导航。Windows 的正式页面服务端渲染、目录并发、延迟加载、浏览历史和目录显示专项 60 项通过。实际点击等待与脚本请求顺序以上线后的同条件复测为准。

整合时，Windows 和 WSL 的现行验证均发现三条路由回归无法启动。测试独立执行页面的读取逻辑，原夹具缺了新加入的模块加载函数。补齐后，15 条读取用例逐项通过，并能验证路由就绪前不会预载、详情代码仍在等待时目录已发出，以及预载失败后目录和返回仍可用。
