## 先读：发指令前的十项检查
1. 先写明当前设计需求文件版本及目标团；目标必须是可见产品增量或明确的技术阻塞消除，不能拿打包、清单、测试数量冒充功能进度。
2. 标明真正的目标仓库/站点、分支、提交。根 Next sandbox 与 `apps/idol-site` 原生源码不是同一个基线。
3. 输入必须实际存在且可读：文件、版本、大小、SHA、必要依赖、启动方式。主会话能读不等于接收会话能读。
4. 先验证输入链，再布置实现；缺文件先补交，不让执行者猜代码或重新搭通用外壳。
5. 明确执行环境、服务环境、浏览器环境及端口；三个位置不能靠“本地”一词含糊带过。
6. 指定允许修改的文件/模块和禁止修改的用户数据、权限、生产服务及部署边界。
7. 明确实现、类型/测试、完整构建、真实浏览器验收与集成的实际负责人，不把固定主会话或云电脑作为所有开发前提。
8. 写出失败时的停止条件、精确回报内容和可继续的独立工作，避免反复撞同一阻塞。
9. 指令正文完整放在【】内；正文外标明目标会话、推荐模型/推理级别及理由。不要所有任务一律最高级。
10. 按共享 STATUS/worklog 跟进任务与收官反馈；Astra 已收官，Sol 最终反馈仍待回。已交付、已转发、已执行、已验收、已上线分别记录，不能互相替代。

## 2026-10-21 事故与改进

> 以下是当时事实与经验，保留其日期；“仓库只有沙箱”等描述不代表 2026-10-22 原生源码导入后的当前仓库状态。当前入口与授权以本文顶部及 docs/codex 为准。

### 1. 未提供真实源码，却要求完成主站接入
现象：Sol 能做孤立候选或通用宿主，但无法按真实生产结构接入；多轮交付变成壳和说明文件。
已核实：GitHub 的 idol 是代码沙箱，不含完整生产后端。Sites 生产源码来自另一源码仓库。旧本地 checkout 或 GitHub 中找不到生产 commit，不等于源码丢失。
纠正：从正确来源恢复生产源码，核实 HEAD，导出必要源码和依赖说明后再派工。发布产物归档不是源代码；摘包也不是可独立运行的完整站点。
后续规则：
- 首先要求读取 README、SOURCE-MANIFEST、真实入口及相关依赖。
- 明确摘包缺哪些构建环境，由谁完成全量 build。
- 缺依赖时回报精确路径；不猜契约、不用旧 main 替代、不增加“通用宿主”来伪装完成。
- GitHub 文档提交不代表 Sites 上线；禁止把本沙箱直接部署覆盖生产。

### 2. localhost 与浏览器跨环境
现象：用户 Windows Chrome 打开 127.0.0.1:8847/example/adya.html?group=adya，显示 ERR_CONNECTION_REFUSED。
确定事实：浏览器所在环境的该地址未成功接受连接。
后续新增证据（同日 v2 交付检查）：evidence/v2-browser-status.json 的 localCommandProbeError 记录 urllib.error.URLError: <urlopen error [Errno 111] Connection refused>，即命令端 HTTP 探针也失败。不能只归因于浏览器跨机器。仍需检查服务是否未启动、已退出或端口不一致；不得把推测写成已证实根因。
历史证据：曾出现执行环境 HTTP 检查通过、浏览器仍拒绝连接；同环境浏览器后来完成了验收。
后续规则：
- localhost 永远指调用者所在机器/网络环境。
- 先核实进程存活、实际监听端口及 HTTP 响应，再确认浏览器和服务是否同环境。
- 云端服务不能直接用用户电脑的 localhost 地址访问。只能使用同环境浏览器或受支持的预览入口。
- 不反复刷新，不要求用户修改防火墙，不擅自建立隧道或扩大网络访问。
- 浏览器不可用时继续代码/静态/HTTP 测试；如实交付未验项，由主会话在已验证环境复验。
- 先记录 Browser 工具是否可用；不可用时仅采用该执行环境支持的 Playwright 等正规路径。
- 环境断开只影响尚未完成的工作，不追溯否定已经保存的验收结果；下次使用前重新检查可用性。

### 3. 工作拆得过碎，短轮次只有包装增量
现象：几轮执行很短，产生预检、映射、打包、清单，却没有相称的页面改善。
纠正：任务按完整可验收功能闭环拆分，而不是按文件数量拆分。
- 补图任务必须接入现有页面、详情及查看器，改变用户能看到的结果。
- 接入任务必须对真实源码提供隔离补丁，而不是新增独立演示外壳。
- 检查耗时短不能直接判定模型弱或任务成功；先检查输入、依赖、任务范围与实际 diff。
- 提高推理级别不能弥补缺源码、不可达网络、不可用浏览器或缺真实素材。

### 4. 验收层级混淆
必须分别记录：
A. 文件可读与 SHA/清单一致；
B. 语法、类型、单测与静态引用；
C. HTTP 返回和图片真实解码；
D. 真浏览器布局、交互、键盘/焦点；
E. 对生产源码的完整构建及回归；
F. 生产部署与在线验证。
不能从 A/B 推断 D/F。不能把上一版本、上一外壳的验收移植给新代码。
- HITGS 占位图验收不等于真实图片验收；26 个资源、59 个槽位是不同指标。
- 真实 BFCache 要观察实际跨文档返回及 persisted；手动触发 pageshow 不是同等证据。
- 不为命中 BFCache 修改必要的私有 no-store 策略。
- 图片查看器测试包括 Tab、Shift+Tab、Escape、关闭后焦点恢复、卸载重挂；移动端要检查实际点击遮挡。
- 桌面窄宿主与真实窄视口分别测；单一标题不溢出不等于整页不溢出。

### 5. 网络失败、素材缺失与错误归因
现象：视频缩略图请求曾得到 HTTP 200 但内容是 Site Unavailable HTML；后来一次请求在隧道阶段被 403 拒绝。
规则：
- 200 不是图片成功，检查 Content-Type、实际字节、解码、尺寸和哈希。
- 网络隧道 403 不等于目标 CDN 返回 403；保留失败层级，不猜来源。
- 已确认访问拒绝后停止该路径，不换代理、域名或身份绕过。
- 不反复生成无法落地的下载清单；继续有实际素材的独立任务。
- 不能拿历史拼图、其他 MV 或低清缩略图填充未匹配槽位；缺失状态诚实保留。

### 11. Shadow DOM 焦点、模拟测试边界与同环境验证

#### Shadow DOM 焦点
- document.activeElement 在 Shadow DOM 内部控件获得焦点时可能返回影子宿主，而非真实按钮。焦点循环、重试前后焦点转移和关闭返回不能只依赖这个值。
- 从所属 Document 或 ShadowRoot 获取活动元素，必要时沿嵌套 shadowRoot 查找；普通 div 没有 activeElement。
- 同时验证普通 DOM 与真实 Shadow DOM。错误态包含关闭、重试两个按钮时，Tab 和 Shift+Tab 都应能访问；重试成功后按钮隐藏时，焦点必须回到有效控件。

#### 模拟测试漏检
- 把 focus() 简化为写 document.activeElement 的模拟 DOM 无法证明影子根行为；未模拟 CSS cascade 的测试也无法证明 hidden 图片实际不可见。
- 保留快速单测，但真实浏览器要核查 computed style、布局矩形、双向 Tab、鼠标与键盘重试、Escape 返回和卸载重挂。
- 正常图片路径通过不等于失败路径通过；页面图片与查看器图片分开复现和判定。模拟失败时避免已解码图片缓存造成假通过。

#### 同环境验证方法
- 先确认服务器与浏览器实际运行在同一执行环境、服务监听且能返回响应，再导航；拥有浏览器二进制不等于浏览器能启动。
- 浏览器尚未启动时的环境故障不是页面缺陷，不修改正常应用代码或削弱系统权限来补偿。
- 需要更换验证环境时，使用正式工具支持、已获授权的相关任务，由它在自己的权限范围内执行。不得转移受禁文件读取或被拒绝网络动作以绕过限制。
- 接收环境自行取得固定版本输入并核对哈希；使用合成业务数据、只读本地图，导航前阻止真实 API 和外域请求。
- 最小测试宿主必须保持真实组件字节不变，并明确范围：客户端行为验证不是完整服务端渲染、登录、真实数据、私有存储或上线验收。

## 2026-10-21 后续集成补充

### 12. 先分清字段语义，再做发布规范化
- 原 ZIP 的 entry/originalPath 可能只是未被消费的归档溯源，也可能参与身份或质量匹配；不能仅凭字段名判断。
- 先查实际消费者、路由/身份计算和 resolver，再决定是否从运行时移除；完整原值保留在交付溯源中。
- 用模型深比较、图片 descriptor、渲染输出和身份映射证明等价；不要把路径编码成别的字符串来绕过检查。
- 清单同时含 sourceSha 与 candidateSha 时，前者可能是原交付，后者才是已规范化并实际验收的候选。核对 overlay 声明与精确差异，不把字段选错当输入漂移，也不跳过校验。

### 13. 媒体保护与详情布局要一起验证
- fromis_9 的桌面缺陷由详情 flex、图片内联尺寸保护及查看器插入的按钮共同造成：图片占满容器，按钮变为额外子项，文字列被压至零宽。
- 修复应把图片和预览按钮包在同一有界媒体列，文字列保留合理的最小宽度约束；无图详情不应留下固定空列。
- 不能通过移除清晰度保护、隐藏图片、强制裁图来消除溢出。
- 同时测实际视口与桌面窄宿主，检查整页 scrollWidth、资料列宽、查看器失败重试及焦点。静态网格规则存在不等于浏览器已过。

### 14. 发行、影像与时间轴需要独立核对
- 目录已有发行不代表时间轴已有入口；单向能打开不代表反向和返回上下文正确。
- 平台发行日期、原地区首发日期、公告日期、团体出道日期须区分。来源口径冲突时先限定展示文案，不随意改日期。
- Acoustic、日语版、OST 等有独立载体证据时应独立建只浏览候选，不并入原版；没有精确封面就留空，没有证据的视频关系就保持未知。
- 只浏览候选和时间轴展示键不是生产记录 ID，不能启用原生写入或冒充已绑定。
- 报道配图来源链接必须与卡片详情链接分离，禁止嵌套 a；缺图时仍保留来源说明，报道图不冒充视频截图。

### 15. 构建空间、依赖复用与最终版本保护
- 工作盘余量与主站发布包余量是两个指标，不能混称存储扩容。
- 删除旧构建或依赖须遵循当次明确批准的目录范围。一次清理许可完成后不自动覆盖下一轮；源码、原图、证据、当前最终版本不能顺带清理。
- 清理 node_modules 前核实真实目录、符号链接、硬链接和活跃依赖目标；保留锁文件，并实测清理前后可用空间。
- 联合集成优先一棵独立源码树、复用同锁依赖、只复制一次必要 public；不要每个检查再生成整套源码/依赖/发布副本。
- “旧目录”可能已被复用为当前最终产物，不能根据旧清理名单再次删除。
- 生成文件名改变时，先证明新旧 carrier 的完整字节、SHA、大小及相关守卫。只允许精确确认后的路径迁移；内容变动需独立审阅，不能盲复制其他候选的 pin 或放宽匹配范围。

### 16. 补丁必须能独立应用，完整 after 文件仍须验 SHA
- 无尾换行文件生成 unified diff 时必须正确输出标准无换行标记及段分隔，否则可能出现下一段 header 粘到上一行的格式错误。
- 交付前在精确基线做 apply --check、实际 apply、after SHA 与 reverse 检查；源码单测通过不能替代补丁可应用性。
- 若补丁格式失败，不可宣称应用成功。可在明确记录失败后采用包内完整 after 文件，但必须逐项核 before/after SHA，证明是同一已验增量，不能借机扩大修改。
- 修复交付工具不应悄悄覆盖已验版本的 Library 输入；保留原证据，新增校验版并明确版本关系。
