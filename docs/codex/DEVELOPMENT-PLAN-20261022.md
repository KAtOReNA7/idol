# 项目分析与开发计划 · 2026-10-22

这是对用户“分析项目，给我你的开发计划”的回答与跨电脑接续记录。计划以真实工程和最新任务记录为依据；本轮只分析与保存计划，不实施新产品代码、不发布。后续优先级可随用户反馈调整。

## 1. 产品目标与当前阶段

网站服务于长期的女团欣赏与个人记录：从一个有自身审美的团体页面认识成员，找到她参与的准确版本作品，观看 MV 或舞台，记录评分与感想，然后继续观看或日后重温。成员、作品、发行与发展历程之间的关系，应帮助用户理解这个团。

每团有独立的构图、字体、照片表达和内页体验；共享底层数据、观看队列、导航与保存协议。评分、备注、观看记录可公开阅读，编辑仅限 owner。核心交付是可打开、资料可信、可连续使用的网页。

当前处于“已有完整正式工程、多个独立设计成果，逐团完成真实接入与验收”的阶段。下一阶段成功标志是完成一团端到端交付，再按每批 2–3 团推进。路由数量、候选文件数量或构建通过不能替代整团验收。

## 3. 近期执行顺序

### 里程碑 1：GENBLUE 完成一次可验收交付

用户结果：能打开当前版本，从团页认识成员、看准确作品、进入已有评分手帐，再返回原来的浏览位置。

1. 在 PR #3 最新版本继续，修正 0.1 评分步进；有界适配 `tests/editor-flow.test.cjs` 的模块依赖，使保存保护测试实际运行到交互断言。
2. 检查 0、null、0.1、清空，MV/舞台/成员/造型评分对象，未保存离开、失败保留输入、冲突及不确定重试。复用现有保存协议；真实写入仅在已授权且可恢复的测试环境和记录中进行。
3. 审查新旧 YOUNG POSSE 编译文件与原图映射后修复构建校验兼容性，继续跑完整裁剪链。保留 GENBLUE 7 张在用 JPG 与所有源原图。后续 UNIS 字体审计也绑定 UDTT 编译文件，这是待检查依赖，尚未证明会失败。
4. 对最终交付构建实测展开 TAR：不超过 256 MiB，且至少留 2 MiB 余量。源码体积和压缩包体积均不能代替该测量。
5. 在明确允许访问的预览环境完成真实浏览器验收，不绕过上一轮访问拒绝；记录 URL、commit、数据模式、真实尺寸和缩放。若仍不可访问，该项继续记受阻，可独立推进的源码与资料任务继续进行。
6. 并行核 8 张准确视频图及《夜市王》成员参与证据；查不到时保留诚实缺项，不借用封面或推断阵容。缺项影响哪些页面逐项列明，不把已完成部分全部扣住。

验收出口：本轮真实预览可打开；首页→成员→准确 MV/舞台→已有记录→返回有操作证据；基础错图、断链、溢出已由开发侧排除；设计与事实剩余项清楚后交用户判断。存在未测的真实保存时，不称全链路已验收。

### 里程碑 2：WOOAH 原生接入

用户结果：第二个完整可用、与 GENBLUE 有明显视觉区别的团体体验。

- 使用 `combined-integration` 的 native v1.2，保留黑色时尚摄影方向；Photo v1 仅用于设计溯源，不覆盖新源码。
- 当前五人与历史 SONGYEE 分开；逐项核八条发行研究记录与实际记录 ID，未绑定条目保持浏览态。
- 并行补 24 张具体视频图、参与关系、SORA 履历及发行目录完整性；只采用可靠证据。
- 接入已有 catalog、作品观看、评分和返回机制，并按里程碑 1 的同类标准独立验收。

### 里程碑 3：izna 与 ifeye 双团批次

用户结果：两套已有设计在正式工程运行，成员、作品与个人记录相互连通。

- 对照 v3 清单接入源文件与现有原图，先完成宿主、runtime resolver、稳定 ID 和记录入口。
- 两团分别检查长页、内页风格、准确视频、评分/返回和手机体验；先完成的一团先交付。
- 不把素材齐全、isolated 候选可运行或一团通过扩展为双团整包通过。

### 里程碑 4：其余原定 30 团按证据与成熟度推进

每批 2–3 团，批前确定本轮具体页面与验收出口，批后交真实网页。先关闭已有成果的明确缺口，再安排需要重新设计的部分。VCHA、Cherry Bullet、Weeekly 可作为下一批候选：分别核完整连续体验与封面回退、原生 Figma/实图终验、六张舞台图和历史肖像来源。其他团先核当前证据再排序，不承诺未经审查的完成日期。

持续保护 Billlie、UDTT 4+1、YOUNG POSSE、i-dle 已认可设计，以及 KATSEYE/AtHeart、IZ*ONE/fromis_9、EVERGLOW/Rocket Punch 的后续资料与布局修正。MEOVV B 继续作为独立候选处理，不顺手混入上述批次或视为已发布。其他历史团保持现状，范围变更另行明确。

首个完整预览与验收闭环结束后，再按真实接入和修订耗时估后续日期。目前采用交付里程碑排期，避免用“源码已交接”推算整团完成时间。

## 4. 每团共同的完成标准

| 维度 | 最低证据 |
| --- | --- |
| 页面与审美 | 团首页、成员目录/详情、发行与作品库、准确 MV/舞台详情、已有评分手帐、只读单根时间轴；全员适用照片与中文名可见，内页延续本团表达；用户人工认可单独记录 |
| 连续使用 | 首页→成员→准确作品→记录→返回；搜索、筛选、观看队列、合理滚动与焦点恢复；原图查看、Escape 与关闭后恢复 |
| 资料准确 | 稳定 ID、精确 videoId、具名图片、当前/历史成员区分；发行不冒充视频，录音参与不推定视频出演；未知保持未知 |
| 评分与权限 | 0–10、0.1 步长、0 与未评分区分；各评分对象不串；公开只读与 owner 写入边界；保存成功/失败/冲突/不确定结果可理解 |
| 真实渲染 | 对当前 commit 检查 320/390/1440/2048/2560 真视口及原生 80/100/125% 缩放；长页、手机触控、图片、溢出及运行错误有证据 |
| 工程与交付 | 对应版本类型/构建、必要回归、完整资源和容量检查；可打开预览及 commit 对应；生产发布需要当前明确授权并另记线上验证 |

设计、功能、事实、部署四项分别记录通过/失败/未测/受阻。SSR、合成数据、旧截图或历史测试不替代当前真实环境证据。基础 QA 由开发侧承担，用户主要确认内容和审美方向。

## 5. 实施与协作方式

- 主集成人负责当前一团的网页闭环与共享保存/导航文件；资料研究与单团组件可并行，避免多人同时改共享入口和 STATUS。
- 保持现有框架、catalog/save API、部署项目身份及数据分区。只在具体问题要求时提取可复用的非视觉逻辑，不先做全站重构或统一皮肤。
- 每轮从最新远端及任务 worklog 接续；独立任务分支，合规 WIP 与验证结果一起推送。STATUS 保持简短索引，细节写任务 worklog。
- 记录实际 commit、改动页面、数据模式、命令与结果、预览链接、四项阶段、剩余问题和下一步最小动作。其他电脑可以不依赖聊天记录继续。
- 当前计划只新增文档，不重测上一轮构建，不改真实评分/备注/观看状态，也不把现有快照公开授权扩展到新数据。
