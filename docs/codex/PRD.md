# 女团资料与作品观看评分网站产品需求

正式工程在 `apps/idol-site/`。本 PRD 适用于 51 团的团体资料、作品观看与私人手帐。2026 年 11 月 22 日确认的要求适用于后续迭代。当前验收结果、开发顺序和协作方式分别见[项目状态](STATUS.md)、[开发路线图](PROJECT-AUDIT-AND-ROADMAP-20261121.md)和[仓库协作指南](../../AGENTS.md)。

## 用户确认的开发与验收要求

《BILLIONAIRE》首发版已通过站内播放验收。后续发布复用正式站实测记录，只有用户报告新的播放故障或该作品更换片源时，才针对变化静音短测一次。当前播放工时优先给仍无法观看的作品。[正式站实播记录](evidence/20261122-v236/formal-billionaire-2160p.json)

1. **减少哈希、备份和例行确认。** 常规改动复用已有核验结果、授权和版本记录。保留原件投递、受限素材及私人写入所需的校验，把开发时间优先用于系统访问、功能迭代和设计统一。
2. **逐页删除与使用无关的信息。** 设计理由、信息组织逻辑、数据匹配过程、核查进度和重复说明进入开发记录。页面保留浏览团体资料、认人、辨认版本、观看、评分、返回和处理失败所需的信息。检查范围包括按钮、图注、空态和辅助功能标签。
3. **同页展示 MV 和专辑时，MV 板块在前。** 团体首页、作品目录及其他混合页面均适用。在手机和桌面检查实际显示的 MV 卡片、专辑封面和操作入口的位置，特别检查并排网格与响应式换行。
4. **从全项目审查推进到上线。** 同时检查本地正式工程、GitHub 仓库和正式站。针对现有内容优化、已上线内容的替换、美学调整与后续开发，写明顺序、工具及完成条件。按获准计划实施、测试、发布，使用同平台、同输入的前后数据说明提升。
5. **按阶段并行开发。** 将互不依赖的片源核查、团页设计、功能和测试分给子代理，协调共享文件。网络或连接恢复后从上次结果接续。飞书是额外的问题来源，处理问题期间继续推进站内播放和其他已批准的开发。
6. **按真人路径遍历 51 团的每个页面。** 使用脚本操作团体入口、成员、搜索与筛选、MV、舞台、发行、时间轴、评分和返回，按各团实际页面逐项记录。发现明确问题即横查全部团体并修复。可能不便且有多种取舍的地方，记录具体页面、操作、障碍和可选改法，提交用户讨论。[现有使用问题](20261122-USABILITY-DISCUSSION.md)
7. **站内播放准确版本，B 站禁用低清。** YouTube 作品与 B 站作品都应在本站直接观看。两平台收录同一剪辑时，由开发者比较正式作品页的起播、实际解码尺寸和选档能否留在站内，选定最可靠的一条。前台展示这个入口，默认起播尺寸与手选最高档分别记录。不同舞台、分 P、剪辑或节选保留各自的版本与评分关系。B 站可由用户登录，播放须达到原片和该账号实际可用的最高档。选档后跳到原站、降为低清或上游报错均记为未通过，移出合格线路。有来源但无法起播的作品保留记录和可操作的失败提示。
8. **只用 Codex 自带浏览器，禁止 Chrome。** 测试尽量在后台，全程静音。每个实播样本只测数秒，记录两个递增的播放时间、实际解码宽高及能可靠测得的实际码率，读不到的指标写「未取得」。发现低清即停止该次 B 站播放。测完关闭测试和意外跳转的标签，保留用户正在使用的标签。
9. **所有可评 MV 的成员评分入口紧跟本人照片。** 在桌面与手机点开成员照片下方的入口，核对同卡的成员名、表现分、造型分和保存反馈。本人可编辑并刷新读回，访客遵循既有只读权限。旧评分、备注、观看状态及历史成员关联继续有效，无真人出镜的作品沿用作品整体评分。[成员评分验收](worklogs/20261122-inline-mv-scores.md)
10. **按代表时期的官方设计复核团页与 MV 成员图。** 先 IVE，以《LOVE DIVE》时期官网、发行宣传及 Figma 桌面和手机画稿核对深蓝、银色、学院造型和确切团标。再依次处理 NewJeans、ADYA、W!TCHX，随后覆盖其余团体。逐团检查过多留白、缺少时期依据的白底或默认字体、错误 logo 和风格不一的成员图片。替换表情失真、低清或时期错配的默认 MV 人像，核对姓名、出处和适用作品，保留原图及每团独立风格。[IVE 官网与画稿](worklogs/20261121-artist-brand.md)
11. **用飞书 CLI 跟进每条问题。** 使用 `lark-cli` 登录、读取用户指定的问题文档，每一条均核查 51 团。修复并在正式站验证后，在对应问题原文后标记「已解决」。仍可复现或仅通过本地验证的条目继续跟进。
    所有设计任务都必须在项目 Figma 中完成，包括共用界面、局部布局和全部团体。设计缺失时先撤销该项视觉实现，在相应画板上依据官网、发行页和原件重做，再落到代码。交付应指向该次变更的可编辑节点，核对桌面与手机的真实页面。
    本轮 51 团人工审核补充了首页要求。团名、团标和成员在首屏清晰可辨。IVE 采用《LOVE DIVE》时期的官网视觉，首页标题用 IVE，保留原版 MV 和独立的发行详情。STAYC 以 High Up 的蓝底六人照定色。每团从自己的官网字标、照片和排版出发。公司、首发日期和宣传语只在有助于识别资料时出现。团体索引统一展示公司，团体首页各保留一段事实简介，作品页统一用「成员与评分」。
12. **GitHub 只保留有效的开发入口。** 保留指向用户验收版本的 `main` 和当前 `codex/project-optimization-20261121`，两条含独有提交的旧线存为可恢复标签，收起冗余分支及过时草稿 PR。推送后从 GitHub 读回。交付说明分别列出已修改、已上线、已在正式站实测及仍待解决的内容，注明测量条件。[仓库整理回执](evidence/20261121-repository-and-routes/github-consolidation.json)

## 产品目标

让用户方便地认识团体与成员，按真实作品和具体视频观看，记录评分与感想，并在成员、作品和团体历史之间连续探索。

- 每团具有符合自身音乐与视觉表达的完整页面，不是同一模板换色。
- 成员身份、中文显示名、历史阵容、作品与影像版本准确，真实图片可辨认。
- 团体、成员、MV、舞台、评分和返回导航形成连续路径。
- 保留现有评分、备注、观看状态、稳定 ID、关联与保存语义。
- 用户验收可打开的成品网页。源代码、ZIP、测试数量或交接说明不是网页成品。

## 范围与优先级

当前范围是正式工程中的 51 团、共用手帐、视频来源及发布链路。优先处理用户遇到的站内观看、系统访问和保存问题，同时推进已确认的逐团视觉调整与可用性修复。日常维护复用已有合格设计及素材。[当前优先顺序](PROJECT-AUDIT-AND-ROADMAP-20261121.md)

以下不属于默认范围：

- 平台重构、替换现有后端、另建评分或保存系统。
- 推翻已认可设计，或强制所有团使用统一视觉模板。
- 为补齐台账而新开全量 MV 同造型照片工程。
- 因缺图删除真实作品，或用假图片、假作品和假保存结果补齐界面。
- 未获授权的生产数据改写、访问范围变更、凭证创建、付费或不可恢复删除。

## 必备页面与连续体验

每团至少覆盖以下完整页面或等价的可用页面状态：

1. 团体首页：有依据的团体介绍、适用名册、作品入口和历史入口。
2. 成员目录：全部适用成员真实照片与中文名直接可见，不靠轮播、分页或弹窗才认全人。
3. 成员详情：具名肖像、可信基本信息、成员历史及精确关联的作品。
4. 作品库：区分唱片或发行与具体影像；支持现有搜索、筛选和观看路径。
5. MV 与舞台详情：保留具体视频身份、版本、参与成员、作品信息和现有评分入口。
6. 评分与既有手帐：清楚表达评分对象、未保存、成功、失败和冲突状态。
7. 单根只读时间轴：精选大事、最早在前，并提供必要关联与返回。

同团内页延续首页的艺术语言，不能在成员、作品或评分页退回通用后台卡片。至少实测“首页 → 成员 → 关联作品 → 评分或既有手帐 → 返回”的连续路径。候选中未接入真实保存的环节必须明确，不计全链通过。

## 每团独立设计

团页重设计先检查已有成果，查阅代表时期官网、发行方宣传和当期作品，再在现有 Figma 文件中使用真实素材形成设计，落实到 React 或对应原生页面，在 Codex 自带浏览器中按实际尺寸验收。

- 参考研究必须实际看过画面与结构，记录可复用和不采用的判断。HTTP 成功、OG 图或事实网页不等于视觉研究。
- 独立判断构图、图形、字体、材质、图片比例和交互节奏。可以共享数据与功能契约，不能共享视觉底板再换色。
- 不从旧 JSON 编造品牌标语、故事卷宗或“某某档案”主题。不要把开发状态、审计措辞和来源局限堆在前台。
- 检查完整长页，而非只看首屏大标题。留白应服务阅读，不能出现标题独占一列、内容缩在另一列造成的失衡空洞。
- 保留已认可的 i-dle、v185 Billlie、UDTT 4+1 和 YOUNG POSSE 设计。修复问题不等于整体改版。
- UDTT 保持四人与陆雨婷的独立分侧表达，陆雨婷身份与图片必须正确。
- GENBLUE 的 BlueCut 与 WOOAH 的黑色时尚实图方向分别处理，不合并成同一皮肤。

Figma 必须有实际目标页面、节点映射、关键截图和实际设计上下文取稿证据。旧网页导入、孤立节点编号或未经执行的设计代码不构成原生设计验收。工具不可用时继续不依赖它的研究、素材或代码工作，并准确标注待补；不能绕过明确访问限制或用另一账户消除额度限制。

## 图片与资料准确性

- 使用高清真实团体图、具名成员图与正式发行封面。优先已有合格原图，同套素材优先；不同时期混用应保留来源与时期说明。
- 人物身份来自具名来源与稳定 ID 映射，不靠脸猜人。禁止 AI 生成成员照片、错配肖像、拉伸人物或放大低清图冒充高清。
- 保留原始素材与已有的可恢复版本。展示裁切经过实页检查，确保关键人物与画面完整，人物比例准确。
- 发行封面只能作为发行封面，不能冒充 MV 截图、舞台图或成员造型图。MV 相关图片须绑定精确视频版本。
- 缺图保留真实作品，用克制且诚实的缺图状态，不借用其他视频或发行的图掩盖缺失。
- 中文成员名默认可见。沿用已核显示值，转写不能冒称官方中文本名。
- 身高、体重等资料有可靠来源再写；缺失不猜。公司、品牌名、活动状态、社交数据等应保留来源与核验日期。
- 当前名册与历史名册分开。加入、退团、暂停、恢复及公告日期的边界须可核，暂停不等于退团，预告不等于已发生。
- 后来的成员名册不能外推到早期 MV 或出道阵容。成员作品关系依参与证据，不把“查看全作品”伪装成个人关联。
- 新研究条目不是自动存在于资料库的真实记录。未绑定的发行或影像候选只浏览，不伪造稳定 ID、评分或保存入口。

## 数据与评分契约

公开页面遵循当前获准的评分、备注和观看状态投影，编辑及私人保存与导出须通过 owner 鉴权。用户于 2026-10-22 13:22 UTC 授权当时的快照随源码进入公开仓库。新私人导出、凭证、密钥和认证令牌保存在仓库外。

- 保留当前稳定 groupId、memberId、workId、ratingId 以及精确视频 ID。禁止以列表位置建立关联。
- 评分范围为 0–10，步长 0.1。0 有效，null 表示未评分；清空不能写成 0。
- 作品 MV 评分、绑定舞台评分、成员相关评分及造型评分保持既有语义，不串对象，不向舞台新增个人评分体系。
- 不从前台是否显示按钮推断写权限，必须保留服务端 owner 校验、字段白名单、版本冲突与既有保存保护。
- 保留未保存离开提醒、明确保存反馈、失败重试与不确定结果处理。不能因重试重复写入或错误显示成功。
- 返回保留合理的筛选、滚动、焦点与导航上下文。图片查看器可关闭，支持 Escape，并恢复焦点与滚动。
- 本地浏览和保存验证使用标明来源的只读公开投影或隔离合成数据。正式站读取单独记录，真实写入使用本人确实要保存的内容。

实现时以实际源码的类型、字段映射和保存策略为准，不根据本文另造字段。关键入口见当前状态文档。

## 时间轴

- 只读、单轴、最早到最新，只展示对理解团体有价值的大事。
- 不做分类多轴，不加分类或排序控制，不称“某某档案”。
- 前台以日期和事件为主，关联显示成员名或作品名，避免开发编号与核验面板。
- 公告日、实际发生日、MV 公开日、音源或专辑发行日各有语义，不能混成同一天。
- 保留已知年月精度，未知日期不猜。不能为满足排序伪造日期或事件完成状态。

## 多尺寸与验收

主要页面覆盖 320、390、1440 像素真视口，并检查 2048、2560 大屏，以及 80%、100%、125% 浏览器缩放。窄容器、真视口和浏览器缩放是不同检查项，不能互相替代。

逐页核对中文长名、导航、评分输入、作品信息、横向溢出、人物比例与留白。设计、功能、资料和上线范围分别记录。沿用的页面检查项可查阅[10 月验收清单](ACCEPTANCE.md)，当前浏览器、开发顺序和签收方式见本文开头的 12 项要求。

## 多台电脑共享开发

GitHub 同时保存代码和可接续的开发阶段。每次开工先检查未提交改动、fetch 远端，阅读 `docs/codex/STATUS.md`、相关任务 worklog、活动分支和 PR，不能只依据本地会话或本地 LOCK。

在当前开发分支接续，给并行任务分配不同文件或明确合并人。小提交随附必要的变更、实测结果、阻断与后续步骤。STATUS 维护已验基线和下一里程碑，任务细节归入相关 worklog。

换机前提交并推送成果与进度，下一台从 GitHub 恢复。禁止 force push、丢弃用户改动的 reset/clean 或覆盖其他电脑的更新；冲突先比较并保留有效改动。推送前核对仓库实际可见性和数据分享授权；本次现有评分、备注、观看快照已获公开入仓批准，不能据此扩大到新增敏感数据。
