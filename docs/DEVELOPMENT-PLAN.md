# 女团项目：云端协作开发计划

## 当前状态

- 现有线上网站继续服务；本仓库尚未包含完整网站，也尚未接管生产部署。
- 两个隔离云任务已完成开发、测试和专用分支推送；集成测试 35 项通过。此结果仅验证协作链路，不代表网站整体通过验收。
- 第一阶段先迁入纯逻辑与合成测试，再接入真实界面源码和安全的开发数据。

## 执行批次

### 0. 建立可复现开发基线

导入经过审查的源码、锁文件、运行说明和测试；保留线上功能，不重建业务。真实评分、备注、观看状态、数据库导出、图片存储及凭证不进入代码仓库。新云任务须能从干净检出安装依赖、运行测试及类型检查。完整 UI 尚未迁入时必须明确标注。

### 1. 第一批并行开发

源码基线验收后，从 2 个云任务逐步扩展至以下 4 条工作线：

1. 团体与成员详情：每批 3–5 个团体，独立视觉，Figma 设计先行；真实团体合照和具名同套成员素材，百科信息、社交账号、粉丝采集时间、作品评分和成绩数据按证据展示。
2. MV 与舞台：承接团体视觉元素，统一成员造型图布局；成员评分只针对相应 MV，舞台不新增个人评分；保护现有评分语义。
3. 性能与体验：分别测量首页内容出现、图片加载、导航与评分持久化时间；记录测试设备和网络条件，避免用小样本承诺普遍速度。
4. 资料工具：并行研究图片和舞台候选，校验视频版本、文字具名证据、重复和缺项。结构校验不能代替证据核验。正式数据入库由单一写入者执行。

### 2. 扩展推广

依据第一批的实际耗时与返工率估算后续日期。按批发布可访问页面，不等待所有团体全部完成。用户明确纳入范围优先，不无限添加团体。

## GitHub 工作方式

- 每个任务明确目标、输入、文件范围、输出、验收条件和依赖。
- 每项任务使用独立分支；常规交付使用草稿 PR。集成验收前不修改 main 或部署。
- 共享类型、路由、核心评分与持久化代码指定一名维护者；其他任务提出兼容性变更而不抢写。
- 统一集成时核验准确 commit、测试、类型检查、相关交互和保护字段；保存可恢复版本后才部署。
- 不以 completed 状态或一次 API 成功认定完整交付；必须检查实际文件与测试证据。
- GitHub Actions 暂不启用；当前测试在 Codex 云环境执行。

## 产品验收底线

- 以偶像爱好者的观看、识人、评分和探索体验为中心，前台不堆开发状态与原始核验标记。
- 团体索引、团体详情、成员详情、MV 和舞台风格连贯，每团不能仅替换颜色。
- MV 成员图片必须对应精确视频版本并有文字姓名证据；不做人脸识别或外观猜人，不用概念照替代。
- 保留用户评分、备注、观看状态和关联；未公开的数据不猜测，不把缺项当零值。
- 正式图片替换保留可恢复备份，遵守用户具体授权；取消的操作不得擅自恢复。

## 汇报与时间估计

分别列出已上线页面、已补齐资料、待验收功能及阻塞。每批提供可打开页面和实测结果。首批完整源码运行与页面交付通过后，才据实际吞吐更新预计日期。云任务成功不构成 24 小时无中断、无限额度或固定完成日期的保证。
