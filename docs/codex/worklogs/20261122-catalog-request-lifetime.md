# 冷启动时打开作品的目录 502

v234 中，IVE《LOVE DIVE》和 XG《WOKE UP》都曾在点卡后收到 HTTP 502。同期 BADVILLAIN、ODD YOUTH、Kep1er 的团目录也各发生一次。五次错误来自原生目录的读表阶段，五个请求都在等待同一 Worker 中另一请求发起的异步读取。正式日志未保留异常原文。[正式调用记录](../evidence/20261122-v234/catalog-joined-read-errors.json)

隔离环境使用同一份合成 D1、真实 workerd 和两个版本各自的目录代码。让首个 HTTP 请求在数据库查询已经发出、读取尚未完成时结束，随后连续打开同一个作品两次。旧版复现了与正式所有者请求相同的步骤、错误类别、HTTP 状态及补读次数。workerd 在这个条件下会丢弃已结束请求的未决操作，等待它的后继请求拿不到结果。[隔离对照](../evidence/20261122-v235/catalog-request-lifetime.json)

| 隔离操作 | v234 | v235 |
|---|---|---|
| 结束首个请求后，所有者第一次打开作品 | 502 | 200，正确作品，可读个人评分 |
| 同条件下访客第一次打开作品 | 502 | 200，正确作品，只读公开数据 |
| 两种身份随后各再开一次 | 均需重新读表 | 均命中已完成的目录，额外读表 0 次 |

v235 仅在同一个 HTTP 请求内合并未完成的目录操作。作品点击、团页和访客查询之间可以复用已经完成、已核准所有者、快照和数据版本的目录。每次仍按请求的身份读取个人评分并检查数据版本。独立回归还覆盖前一个请求失败、并发保存、切换数据来源和所有者变化。四个目录与详情专项共 56/56 项通过。[读取器](../../../apps/idol-site/lib/idol/native-reader.ts) · [并发回归](../../../apps/idol-site/tests/native-catalog-cache.test.cjs) · [workerd 与 D1 回归](../../../apps/idol-site/tests/work-detail-d1.test.cjs)

两个独立请求同时遇到空缓存时可以各读一次表。隔离用例让第一个请求停在读表阶段，第二个请求独立读表并返回。前一个请求随后失败，再开作品仍命中第二个请求已完成的目录。这里衡量的是并发访问成功率，实际读表成本取决于正式流量中冷启动的重叠次数。

## 正式站打开作品和返回

三个版本各用 Codex 自带浏览器的同个测试标签、375 px 正文和相同作品，每组按同样顺序测三轮。数值为从首页点击卡片到作品页播放按钮可操作的中位毫秒数。v234 的 IVE 单列两条成功读数和第三轮失败。v235 九次均只发一个详情目录请求，九次均可返回团首页。[三版本逐次数据](../evidence/20261122-v235/access-comparison.json)

| 作品 | v233 | v234 | v235 |
|---|---:|---:|---:|
| IVE《LOVE DIVE》 | 2053 | 1466、1428、HTTP 502 | 1490 |
| ADYA《Per》 | 1634 | 2234 | 1406 |
| Cherry Bullet《P.O.W!》 | 3213 | 1448 | 1217 |

v235 在 51 团的每张代表卡都实际量到 375 px 正文。49 团走到共享作品页的播放按钮，ATHEART 和 W!TCHX 走到带原片链接的团内详情，51 次均可返回。首卡及进入详情后记录到的 81 条目录响应全部为 200。v234 的 51 团混合了手机与桌面宽度，因此两次普查分别列数。[v235 正式逐团记录](../evidence/20261122-v235/formal-51-representative-cards.json) · [v234 原始宽度](../evidence/20261122-v234/formal-51-representative-cards.json)

ADYA 第三轮仍花了 3043 ms。浏览器收完 HTML 用时 1051 ms，详情目录请求发出后等到首字节又用时 1507 ms。对应 Worker 未命中缓存，整次调用 1304 ms，其中 CPU 359 ms，原生读取流程 1045 ms。同卡第二轮命中缓存，整次调用 209 ms，CPU 6 ms，原生读取流程 203 ms。这些耗时彼此包含。[五次可对应的成功调用](../evidence/20261122-v235/formal-access-worker-timing.json)

下次访问优化先在隔离库重放同一个作品的冷读和热读，把读表、构建全馆目录、按作品筛选分别计时。目前即使只打开一支 MV，冷启动也要读取各表并生成全馆目录。可先比较将快照存在性查询与读表并行的方案，保留所有者和数据版本核对。若时间主要花在计算，则优先调整实测最慢的投影步骤。在同样三张作品卡上复测，分别报告冷读、热读、失败次数和返回结果。
