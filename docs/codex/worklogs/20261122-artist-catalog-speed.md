# 团页目录与作品入口

从 IVE 首页打开首支 MV，旧团页还会下载该团各首歌待比选的舞台视频。访客看得到已选的节目、节目版本和来源变更记录，首页所需的这些字段现在集中在更小的一份响应中。51 个团页的 34 处取数入口沿用已有的 `Prefer: omit-stage-candidates` 协商。完整读取、导出及既有评分绑定继续使用原契约。

## 目录传输

用相同仓库快照生成公开目录，逐团通过 HTTP 读取两种响应，并逐字段比对。51 团合计从 2,541,326 降至 2,226,494 个解码字节，少 314,832 字节（12.39%）。50 团体积下降，W!TCHX 的作品没有候选数组，两次结果完全一致。逐团合计省去 617 个数组，内含 1,514 行候选。同一作品可能出现在多个团的目录。其余字段全部相等。访客和 owner 两种授权分支、全库与单团协商、完整历史和有效 0 分也有独立的合成数据回归。

| 团体 | 团页旧响应 → 新响应 | 降幅 | 首页请求数 |
|---|---:|---:|---:|
| IVE | 130,554 → 112,759 字节 | 13.63% | 1 → 1 |
| ADYA | 10,368 → 9,824 字节 | 5.25% | 1 → 1 |
| Cherry Bullet | 35,318 → 33,772 字节 | 4.38% | 1 → 1 |

Codex 自带浏览器逐团打开两版首页。50 个可测的真实首页均成功读到一张可操作的 MV 卡，每页各读一次目录。浏览器实际记录的目录解码数据从 2,535,196 减到 2,220,562 字节（−12.41%）。Resource Timing 的传输字节含本机响应头开销，从 2,550,196 减到 2,235,562（−12.34%）。UDTT 的受限首页原件无法在此本地预览挂载，其目录单独通过 HTTP 核对，6,130 → 5,932 字节。

## 首个作品、详情和返回

用同一 Windows 本地生产构建流程、依赖、匿名快照、7,268 个本地团体素材文件、自带浏览器和本地代理复测。每团固定首卡和作品 ID，每个版本三轮，共 72 项操作全部通过。视口预设 1280 × 820，实际正文宽 1265 像素。计时从触发导航或点击到探测到目标，可操作卡允许位于首屏下方。首次取数后导航到同团作品页、从详情返回分别计时。静态资源复用当前浏览器缓存，两版目录均为 `no-store`，本机传输未压缩。正式站 owner 目录和物理冷缓存访问的耗时另计。

| 团体 | 首页首卡 | 点击卡片至详情标题 | 从详情返回首卡 | 团内作品导航 |
|---|---:|---:|---:|---:|
| IVE | 132.6 → 251.7 ms | 462.1 → 535.8 ms | 235.3 → 214.0 ms | 1.0 → 2.5 ms |
| ADYA | 71.8 → 109.2 ms | 458.5 → 529.8 ms | 48.0 → 80.5 ms | 1.2 → 2.9 ms |
| Cherry Bullet | 53.6 → 76.6 ms | 442.9 → 547.0 ms | 34.8 → 76.1 ms | 38.9 → 76.8 ms |

表中为三轮中位数。三团首页首卡和详情标题在这轮候选构建中都较慢。另一个逐团普查每团每版各一次，50 团首页中位数却从 114.2 到 95.4 ms。浏览器会话负载、缓存和最后一次探测间隔都会影响读数，IVE 末次探测的间隔最高达 127.9 ms。目前可以量化的改善是团页目录传输量；首卡与详情等待时间尚需继续优化。[每轮间隔、宽度、请求、字节与逐团数据](../evidence/20261122-v213/catalog-speed.json)

三团直接进入 MV 后，每次都下载 1,955,086 字节的全馆目录。该请求两版相同。下批先从作品详情切入，通过本支 MV、相关版本、出镜成员和对应评分关系提供初始内容，进入全馆搜索或导航时再取完整目录。用同一批作品测详情，同时核对跨团版本、返回、评分保存和重试。

Windows 候选生产构建通过。目录、截止时间、回退及素材绑定定向测试 161 项通过，Young Posse 专项 5 项通过。扩充团页协商断言后重跑的两套测试共 147 项通过。完整构建、测试和正式站复验与整批发布一起记录。
