# 全部个人页模块顺序统一：已实现，未部署

用户已批准统一独立成员页和共享手帐的模块顺序，保留51团各自视觉。本轮从 PR47 `d07242bf99626d1948de6a78919ba037c5fa3658` 接续，实现48团 React 页面、ifeye／izna／UDTT 三个原生页面及共享 MemberDetail。正式站仍为 v202，最新版本和部署状态已分别只读核实；本轮没有保存 Sites 版本或部署。

实际阅读及键盘顺序为：肖像／姓名／所属与历史身份／原图入口 → 基本资料／简介／已有账号 → 原有评分及私人关系作品 → 有证据的公开参与／认人参考 → 经历与动态 → 备注／原有编辑器及来源。没有原有评分面板的页面继续使用经过身份核验的手帐入口；没有证据的经历或参与信息不造模块。公开条目不能创建私人关系。

## 实现与保护

真实移动 JSX／原生 HTML，不通过 CSS order 或视觉定位掩盖阅读顺序。MemberCareerFacts 拆成 intro／history／sources 三个可选段，旧调用默认行为保留；编辑型模板通过精确成员ID及真实当前／曾属关系读取经历。独立页的公开作品入口保留具体作品ID与返回上下文。共享手帐保留原有 owner 编辑器及回调，备注放在经历之后。

ifeye／izna 的真实实现是 Shadow runtime，原生手帐入口在每次路由渲染后挂载到成员专用槽位；精确身份、可用性、脏数据离开和返回焦点守卫保持。UDTT 原控件标记移到公开参与之前，并保留本团 section 内边距。陆雨婷只展示已有专访发布日期，不恢复旧 careerPeriods 的错误入团推断。SASHA 暂停公告、恢复计划及 YOON JI YOON 结束活动公告保持原有语义。

没有修改 data／public／db／.openai／app/api 下的既有文件。全部原件、稳定ID、私人关系、评分／备注／观看记录、访问及 owner 保存鉴权保持。UDTT 仅更新 presentation.mjs 的精确运行时 pin，并记录前后摘要；其他守卫、固定九个排除原件、两个共享海报和完整构建 carrier pin 均未放宽。

新增公开模块遇到损坏的私人关系列表时，无法可靠排除已有私人关系，便暂不展示该公开投影，防止异常评分行使页面崩溃。正常公开条目与已有零分关系继续分别显示。
