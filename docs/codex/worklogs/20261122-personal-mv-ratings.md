## 写入和恢复

部署使用 Drizzle 向前迁移 `0011_personal_mv_ratings.sql`，新增一张独立表和唯一索引。发布包须应用迁移后再由新 Worker 服务本人目录和写入。每次保存把分数、修订及回执放在同一事务；作品来源、人物修订、原生关系、owner 和存储世代均在写入时核对。断网或等待回执超时后，两个编辑器保留原输入和操作号，恢复网络后可以核对同次保存。

本人导出和完整归档均保留旧格式 v1。含新增数据时分别生成 `idol.native-data-export.v2`、`idol.native-archive.v2`，包含同一事务读取的评分与完整日志。独立恢复使用 `python scripts/archive/restore_personal_mv_ratings.py 本人导出.json 新建本地.sqlite`。完整包沿用 `python scripts/archive/verify_restore.py 本地备份目录`。两条命令均在本机新数据库中恢复。原飞书迁移流程会拒绝含原生私分的 v2 包。舞台前像仍计算全量保存日志，只按目标原始作品身份匹配写入。
