# 跨会话派工与验收手册
更新：2026-10-21（北京时间）。适用：女团资料库、网站、Sol / Astra 协作。
这是工程交接规范，不是新增授权。执行时以用户最新要求、当前工具权限和已核实状态为准。

## 先读：发指令前的十项检查
1. 目标必须是可见产品增量或明确的技术阻塞消除，不能拿打包、清单、测试数量冒充功能进度。
2. 标明真正的目标仓库/站点、分支、提交。GitHub 开发沙箱与 Sites 生产源码不是同一个基线。
3. 输入必须实际存在且可读：文件、版本、大小、SHA、必要依赖、启动方式。主会话能读不等于接收会话能读。
4. 先验证输入链，再布置实现；缺文件先补交，不让执行者猜代码或重新搭通用外壳。
5. 明确执行环境、服务环境、浏览器环境及端口；三个位置不能靠“本地”一词含糊带过。
6. 指定允许修改的文件/模块和禁止修改的用户数据、权限、生产服务及部署边界。
7. 区分执行者负责的实现/测试与主会话负责的完整构建、真实浏览器验收和集成。
8. 写出失败时的停止条件、精确回报内容和可继续的独立工作，避免反复撞同一阻塞。
9. 指令正文完整放在【】内；正文外标明目标会话、推荐模型/推理级别及理由。不要所有任务一律最高级。
10. 同时跟进 Sol、Astra 的进度与下一步。已交付、已转发、已执行、已验收、已上线分别记录，不能互相替代。

## 2026-10-21 事故与改进

### 1. 未提供真实源码，却要求完成主站接入
现象：Sol 能做孤立候选或通用宿主，但无法按真实生产结构接入；多轮交付变成壳和说明文件。
已核实：GitHub 的 idol 是代码沙箱，不含完整生产后端。Sites 生产源码来自另一源码仓库。旧本地 checkout 或 GitHub 中找不到生产 commit，不等于源码丢失。
纠正：从正确来源恢复生产源码，核实 HEAD，导出必要源码和依赖说明后再派工。发布产物归档不是源代码；摘包也不是可独立运行的完整站点。
后续规则：
- 首先要求读取 README、SOURCE-MANIFEST、真实入口及相关依赖。
- 明确摘包缺哪些构建环境，由谁完成全量 build。
- 缺依赖时回报精确路径；不猜契约、不用旧 main 替代、不增加“通用宿主”来伪装完成。
- GitHub 文档提交不代表 Sites 上线；禁止把本沙箱直接部署覆盖生产。

### 2. localhost 与浏览器跨环境
现象：用户 Windows Chrome 打开 127.0.0.1:8847/example/adya.html?group=adya，显示 ERR_CONNECTION_REFUSED。
确定事实：浏览器所在环境的该地址未成功接受连接。
尚未确定：本轮服务是否未启动、退出、端口不一致，或运行在另一台机器。不得把跨机器推测写成已证实根因。
历史证据：曾出现执行环境 HTTP 检查通过、浏览器仍拒绝连接；同环境浏览器后来完成了验收。
后续规则：
- localhost 永远指调用者所在机器/网络环境。
- 先核实进程存活、实际监听端口及 HTTP 响应，再确认浏览器和服务是否同环境。
- 云端服务不能直接用用户电脑的 localhost 地址访问。只能使用同环境浏览器或受支持的预览入口。
- 不反复刷新，不要求用户修改防火墙，不擅自建立隧道或扩大网络访问。
- 浏览器不可用时继续代码/静态/HTTP 测试；如实交付未验项，由主会话在已验证环境复验。
- 先记录 Browser 工具是否可用；不可用时仅采用该执行环境支持的 Playwright 等正规路径。
- 环境断开只影响尚未完成的工作，不追溯否定已经保存的验收结果；下次使用前重新检查可用性。

### 3. 工作拆得过碎，短轮次只有包装增量
现象：几轮执行很短，产生预检、映射、打包、清单，却没有相称的页面改善。
纠正：任务按完整可验收功能闭环拆分，而不是按文件数量拆分。
- 补图任务必须接入现有页面、详情及查看器，改变用户能看到的结果。
- 接入任务必须对真实源码提供隔离补丁，而不是新增独立演示外壳。
- 检查耗时短不能直接判定模型弱或任务成功；先检查输入、依赖、任务范围与实际 diff。
- 提高推理级别不能弥补缺源码、不可达网络、不可用浏览器或缺真实素材。

### 4. 验收层级混淆
必须分别记录：
A. 文件可读与 SHA/清单一致；
B. 语法、类型、单测与静态引用；
C. HTTP 返回和图片真实解码；
D. 真浏览器布局、交互、键盘/焦点；
E. 对生产源码的完整构建及回归；
F. 生产部署与在线验证。
不能从 A/B 推断 D/F。不能把上一版本、上一外壳的验收移植给新代码。
- HITGS 占位图验收不等于真实图片验收；26 个资源、59 个槽位是不同指标。
- 真实 BFCache 要观察实际跨文档返回及 persisted；手动触发 pageshow 不是同等证据。
- 不为命中 BFCache 修改必要的私有 no-store 策略。
- 图片查看器测试包括 Tab、Shift+Tab、Escape、关闭后焦点恢复、卸载重挂；移动端要检查实际点击遮挡。
- 桌面窄宿主与真实窄视口分别测；单一标题不溢出不等于整页不溢出。

### 5. 网络失败、素材缺失与错误归因
现象：视频缩略图请求曾得到 HTTP 200 但内容是 Site Unavailable HTML；后来一次请求在隧道阶段被 403 拒绝。
规则：
- 200 不是图片成功，检查 Content-Type、实际字节、解码、尺寸和哈希。
- 网络隧道 403 不等于目标 CDN 返回 403；保留失败层级，不猜来源。
- 已确认访问拒绝后停止该路径，不换代理、域名或身份绕过。
- 不反复生成无法落地的下载清单；继续有实际素材的独立任务。
- 不能拿历史拼图、其他 MV 或低清缩略图填充未匹配槽位；缺失状态诚实保留。

### 6. 图片语义与清晰度
- 采恩现有素材是 2023 年出道前表演四联历史拼图，不是新官方标准头像。
- 整图 contain 展示，保留来源和历史标签；标准头像缺失可与历史资料入口并存。
- 不裁成假头像、不拉伸、不冒充其他 MV 截图；低清素材不得写“高清”。
- 保留原有清晰度/展示尺寸上限与已验图片，不为凑齐数目降低身份与来源要求。
- 入库/替换遵循当次实际授权及可恢复备份，不触碰评分、备注、观看状态。

### 7. Figma 工具与额度
- 额度不是一律不能用，优先用于能带来设计决策或可见产出的环节。
- 已遇到上传 405、调用体积限制、格式/API 不支持等路径；没有新证据证明路线变化前，不重复碰撞。
- 查节点、做映射、打包不等于图片已写入 Figma。
- 当日已验状态是 28 个槽位中仅 2 个写入，不能描述成完整完成；这是历史快照，下轮需重新核实。
- 新方案先小样验证，再扩大批量。不能虚构可用额度或把“准备就绪”写成“设计完成”。

### 8. 私有图片服务不是通用图床接口
- 当日生产图片准入和查看契约限定 UDTT；HITGS 接入不能靠放宽这些校验完成。
- 隔离候选可注入只读 resolver 验证真实图片，不能据此宣称生产已准入或上传。
- 不伪造 proof、用 slug 冒充真实记录 ID、不改 owner/active/write/recovery/config。
- 原生跳转只有真实 ID 绑定被证明时启用；不能证明时禁用。
- GET 是只读不代表整个服务没有写能力；读取响应可能含用户私有评分/备注，不应装入交接包。
- 包体预算按同一计量口径验证实际产物；归档体积、展开体积、新增净体积不能混算。不要用估算余量宣称安全上线。

### 9. 指令中的承诺与反馈
- 一发现阻塞就报告准确动作、目标、错误层级、已完成部分、待用户决定项。
- 不让用户连续催问才给状态；长任务有实质进展或超过预期时给简短更新。
- 不在验证前宣布“已解决”“可上线”；也不要把仅已送给用户的指令写成执行者已开工。
- 两会话要分工互不覆盖：各自冻结基线、修改范围和交付接口明确，主会话负责集成裁决。
- 外部会话任务文本必须自包含，不假设共享文件系统、相同工具或完整聊天历史。

## 派工模板
推荐会话/模型与推理级别：按任务选择并说明理由。

【目标：本轮唯一可见增量，以及不做什么。
基线：目标仓库/站点、提交、文件 ID/版本/大小/SHA；先确认实际可读。
环境：代码与服务在哪里、浏览器在哪里、可用验证路径。
允许修改：文件/模块范围；禁止修改：用户数据、权限、未授权生产配置等。
实施：明确功能闭环，不以新外壳/清单代替目标。
验收：执行者必做的检查；主会话后续的完整构建/浏览器/集成验收。
阻塞规则：准确回报缺失路径或错误层级；停止重复失败；继续不依赖阻塞的工作。
交付：最小 diff/必要完整候选、版本与哈希、复现命令、真实证据、明确未完成项。
部署：是否允许；没有明确授权/任务范围时不自行上线。】

## 快速复用与维护
- 每次发 Sol/Astra 新任务前先读本文件和根目录 AGENTS.md，再读取当前交付，不能仅靠上轮总结。
- 每轮更新只追加真实的新教训；已解决/待验证/仍阻塞明确区分。
- 本文件不保存凭证、签名下载地址、用户评分备注、内部运行笔记或完整私有源码摘包。
- 历史数值和故障只用作教训，不自动恢复旧授权，也不替代下一轮状态检查。
