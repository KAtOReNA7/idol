## 产品目标

让用户方便地认识团体与成员，按真实作品和具体视频观看，记录评分与感想，并在成员、作品和团体历史之间连续探索。

- 每团具有符合自身音乐与视觉表达的完整页面，不是同一模板换色。
- 成员身份、中文显示名、历史阵容、作品与影像版本准确，真实图片可辨认。
- 团体、成员、MV、舞台、评分和返回导航形成连续路径。
- 保留现有评分、备注、观看状态、稳定 ID、关联与保存语义。
- 用户验收可打开的成品网页。源代码、ZIP、测试数量或交接说明不是网页成品。

## 必备页面与连续体验

每团至少覆盖以下完整页面或等价的可用页面状态：

1. 团体首页：有依据的团体介绍、适用名册、作品入口和历史入口。
2. 成员目录：全部适用成员真实照片与中文名直接可见，不靠轮播、分页或弹窗才认全人。
3. 成员详情：具名肖像、可信基本信息、成员历史及精确关联的作品。
4. 作品库：区分唱片或发行与具体影像；支持现有搜索、筛选和观看路径。
5. MV 与舞台详情：保留具体视频身份、版本、参与成员、作品信息和现有评分入口。
6. 评分与既有手帐：清楚表达评分对象、未保存、成功、失败和冲突状态。
7. 单根只读时间轴：精选大事、最早在前，并提供必要关联与返回。

同团内页延续首页的艺术语言，不能在成员、作品或评分页退回通用后台卡片。至少实测“首页 → 成员 → 关联作品 → 评分或既有手帐 → 返回”的连续路径。候选中未接入真实保存的环节必须明确，不计全链通过。

## 每团独立设计

设计流程是：检查已有成果与素材 → 实际观看官网、Spotify 等音乐平台及正式作品视觉 → Figma 原生实图设计与取稿 → React 实现 → 实际浏览器 QA → 用户人工验收。

- 参考研究必须实际看过画面与结构，记录可复用和不采用的判断。HTTP 成功、OG 图或事实网页不等于视觉研究。
- 独立判断构图、图形、字体、材质、图片比例和交互节奏。可以共享数据与功能契约，不能共享视觉底板再换色。
- 不从旧 JSON 编造品牌标语、故事卷宗或“某某档案”主题。不要把开发状态、审计措辞和来源局限堆在前台。
- 检查完整长页，而非只看首屏大标题。留白应服务阅读，不能出现标题独占一列、内容缩在另一列造成的失衡空洞。
- 保留已认可的 i-dle、v185 Billlie、UDTT 4+1 和 YOUNG POSSE 设计。修复问题不等于整体改版。
- UDTT 保持四人与陆雨婷的独立分侧表达，陆雨婷身份与图片必须正确。
- GENBLUE 的 BlueCut 与 WOOAH 的黑色时尚实图方向分别处理，不合并成同一皮肤。

Figma 必须有实际目标页面、节点映射、关键截图和实际设计上下文取稿证据。旧网页导入、孤立节点编号或未经执行的设计代码不构成原生设计验收。工具不可用时继续不依赖它的研究、素材或代码工作，并准确标注待补；不能绕过明确访问限制或用另一账户消除额度限制。

## 图片与资料准确性

- 使用高清真实团体图、具名成员图与正式发行封面。优先已有合格原图，同套素材优先；不同时期混用应保留来源与时期说明。
- 人物身份来自具名来源与稳定 ID 映射，不靠脸猜人。禁止 AI 生成成员照片、错配肖像、拉伸人物或放大低清图冒充高清。
- 保留原始素材与可恢复备份。展示裁切应经过实际检查，不丢失关键人物或内容；统一容器不能成为失真理由。
- 发行封面只能作为发行封面，不能冒充 MV 截图、舞台图或成员造型图。MV 相关图片须绑定精确视频版本。
- 缺图保留真实作品，用克制且诚实的缺图状态，不借用其他视频或发行的图掩盖缺失。
- 中文成员名默认可见。沿用已核显示值，转写不能冒称官方中文本名。
- 身高、体重等资料有可靠来源再写；缺失不猜。公司、品牌名、活动状态、社交数据等应保留来源与核验日期。
- 当前名册与历史名册分开。加入、退团、暂停、恢复及公告日期的边界须可核，暂停不等于退团，预告不等于已发生。
- 后来的成员名册不能外推到早期 MV 或出道阵容。成员作品关系依参与证据，不把“查看全作品”伪装成个人关联。
- 新研究条目不是自动存在于资料库的真实记录。未绑定的发行或影像候选只浏览，不伪造稳定 ID、评分或保存入口。

## 数据与评分契约

用户已明确要求评分、备注、观看记录公开展示；编辑仍仅限 owner。公开读取不等于开放写入。用户于 2026-10-22 13:22 UTC 明确选择保持 `KAtOReNA7/idol` 公开，并允许现有评分、备注、观看快照随本次源码交接进入该公开仓库。该批准不推广为未来新增敏感数据或无关导出的公开分享。凭证、密钥和认证令牌始终不能入仓。

- 保留当前稳定 groupId、memberId、workId、ratingId 以及精确视频 ID。禁止以列表位置建立关联。
- 评分范围为 0–10，步长 0.1。0 有效，null 表示未评分；清空不能写成 0。
- 作品 MV 评分、绑定舞台评分、成员相关评分及造型评分保持既有语义，不串对象，不向舞台新增个人评分体系。
- 不从前台是否显示按钮推断写权限，必须保留服务端 owner 校验、字段白名单、版本冲突与既有保存保护。
- 保留未保存离开提醒、明确保存反馈、失败重试与不确定结果处理。不能因重试重复写入或错误显示成功。
- 返回保留合理的筛选、滚动、焦点与导航上下文。图片查看器可关闭，支持 Escape，并恢复焦点与滚动。
- 开发和浏览器 QA 使用明确标注的合成数据。真实数据接入与真实写入验收单独记录，合成测试不能替代。

实现时以实际源码的类型、字段映射和保存策略为准，不根据本文另造字段。关键入口见当前状态文档。

## 时间轴

- 只读、单轴、最早到最新，只展示对理解团体有价值的大事。
- 不做分类多轴，不加分类或排序控制，不称“某某档案”。
- 前台以日期和事件为主，关联显示成员名或作品名，避免开发编号与核验面板。
- 公告日、实际发生日、MV 公开日、音源或专辑发行日各有语义，不能混成同一天。
- 保留已知年月精度，未知日期不猜。不能为满足排序伪造日期或事件完成状态。

## 多尺寸与验收

主要页面覆盖 320、390、1440 像素真视口，并检查 2048、2560 大屏，以及 80%、100%、125% 浏览器缩放。窄容器、真视口和浏览器缩放是不同检查项，不能互相替代。

中文长名、导航、评分输入、作品信息应完整可读；无意外横向溢出、图片拉伸、遮挡或失衡留白。设计、功能、资料、上线四项分别记录，详见 [验收清单](ACCEPTANCE.md)。构建、类型检查或单测通过只能支持工程结论。

## 多台电脑共享开发

GitHub 同时保存代码和可接续的开发阶段。每次开工先检查未提交改动、fetch 远端，阅读 `docs/codex/STATUS.md`、相关任务 worklog、活动分支和 PR，不能只依据本地会话或本地 LOCK。

每任务使用独立分支与 `docs/codex/worklogs/<task-id>.md`，避免多机同时改同一共享文件。小提交一并保存代码、路径、依赖、素材、实测结果、阻断、下一步和版本状态；合规 WIP 可以推送独立分支，未验不混入 main。STATUS 只维护已验基线、下一里程碑与任务索引，任务细节分别记录。

换机前提交并推送成果与进度，下一台从 GitHub 恢复。禁止 force push、丢弃用户改动的 reset/clean 或覆盖其他电脑的更新；冲突先比较并保留有效改动。推送前核对仓库实际可见性和数据分享授权；本次现有评分、备注、观看快照已获公开入仓批准，不能据此扩大到新增敏感数据。
