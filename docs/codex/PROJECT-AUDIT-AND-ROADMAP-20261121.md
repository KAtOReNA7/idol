## 三、优先修复的发现

### 1. 正式锁文件命中严重依赖公告

`npm audit --omit=dev` 报告 6 个受影响包，含 1 个 critical、3 个 high、2 个 moderate。生产依赖中的 critical 为 `next@16.3.4`。包含开发与构建依赖后共 33 个受影响包，critical 为 `next` 和 `react-server-dom-webpack`。本项目同时使用 `vinext@1.0.0-beta.5`、Vite 和 Cloudflare Worker，依赖分类本身不足以判断最终 Worker 的实际暴露面。

优先确认受公告影响的功能是否进入客户端、SSR、RSC 或构建工具，再选择相容的修复版本。每组升级都重新构建并核对 Worker、资源清单、匿名读取和 owner 拒绝路径。若升级改变受保护产物哈希，逐项核对源码、引用与产物差异后再更新对应凭据。[正式依赖声明](../../apps/idol-site/package.json) · [锁文件](../../apps/idol-site/package-lock.json)

### 2. 舞台导入应把现有保护变成不可省略、可恢复的执行流程

正式导入器含 56 个 Python `assert`，身份和选择策略模块另有 29、58 个。包长度及摘要、目标集合、前像新鲜度、日志与来源约束依赖其中多项断言。解释器优化模式会省略断言。正常模式下的 69 项近期回归通过。另一个具体问题是写入阶段依次替换证据、来源、状态三个文件，使用固定临时文件名。单文件替换有保护，进程中断或两次导入重叠时缺少整批恢复边界。

把生产输入校验改为始终执行并给出明确错误的函数。写入前统一准备并校验旧摘要、三个新文件和目标集合。用单写入者约束、唯一暂存路径及可恢复事务记录处理重试。验收须覆盖普通与优化解释器、三个文件替换之间中断、相同批次重跑、竞争写入。运行这些用例只需隔离副本和合成记录。[导入器](../../apps/idol-site/scripts/merge-stage-batch.py) · [来源身份](../../apps/idol-site/scripts/stage_source_identity.py) · [选择策略](../../apps/idol-site/scripts/stage_selection_policy.py) · [现有保护测试](../../apps/idol-site/tests/stage-owner-preflight.test.cjs)

### 3. 现有测试覆盖广，但整套结果暂时不能支撑大规模改动

正式 Node 套件共 **3,956 项，2,764 通过、1,153 失败、39 跳过**，失败分布在 137 个文件。另行复跑最近的 69 项采用测试全部通过，独立的偏好统计套件 31 项通过。旧加载器把模块名拼成 `follower-count.mjs.ts`，单这一条缺文件错误就出现 256 次。两个旧夹具对同一公开媒体模块的导入拒绝另触发 325 次。运行时缺陷、测试夹具失效和只适用于历史版本的断言需要分别查明。

还有两个可独立复现的工具问题。补充片源校验器启动时拒绝当前模块依赖 `./stage-source`，尚未核到输入数据。CSS HTTP 夹具固定期待 37 张主题样式表，实际构建找到 50 张，导致后续处理器测试未启动。现有搜索浏览器脚本在手机宽度首项断言前超时。实际构建的作品列表和返回焦点流程通过。正式 `package.json` 缺少统一 `test`、`typecheck` 和 `verify` 命令。本提交也没有 GitHub Actions 工作流。[测试失败逐文件索引](evidence/20261121-project-audit/verification.json) · [补充片源校验器](../../apps/idol-site/scripts/validate-supplements.mjs) · [CSS 夹具构建](../../apps/idol-site/tests/css-http-fixture-build.mjs)

默认 lint 返回 **2,944 个错误、1,000 个警告**，其中 2,725 个错误来自测试目录。应为 CommonJS 测试配置匹配的规则，将运行时代码的 Hooks、类型和导航问题单独修复。历史断言应在对应版本仍可执行，每次退役都留下对应版本及当下的替代验收。[ESLint 配置](../../apps/idol-site/eslint.config.mjs)

### 4. 用户打开首页就承担了大量详情数据
